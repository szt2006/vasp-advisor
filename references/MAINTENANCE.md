# MAINTENANCE —— VASP skill 维护清单（SOP）

> 用途：往本 skill 里**新增资料**（新讲义 / 新官方页面 / 新实战经验）或**修正已有内容**时，
> 照此流程分层落库，保证"全面、不堆乱、跨对话可复用"。
>
> 配套阅读：`AGENTS.md`「知识分层」、`references/_WRITING_CONTRACT.md`（写作契约）、
> `references/raw/README.md`（溯源层说明）、`CHANGELOG.md`（更正记录）。
>
> 设计原则不变：**顾问，而非自动驾驶**；本清单是"怎么维护知识库"，不是"怎么跑计算"。

---

## 0. 两条最重要的规矩

### 0.1 ⭐ **机器细节不进，结论进**

这是整个设计里最值钱的一条。它的意思是：

| 🟢 进 skill（普世） | 🔴 不进 skill（站点） |
|---|---|
| "每 rank 网格体量可能触发崩溃，**换 rank 数判别**" 这个方法 | "本机阈值 = 2²¹" |
| "用**已知可跑的最小算例**做单变量差分" 这个方法 | "本机某示例能跑" |
| "上线前先跑一次极小算例" 这个动作 | "队列名 / 核数上限 / 服务器地址" |
| "生成物必须 LF、无 BOM" | 某台 Windows 的具体行为 |
| "版本间构造会变，升级后重跑一致性测试" | "本机是某个版本" |
| **探针工具本身**（扫安全包络） | **扫出来的那张表** |

**为什么重要**：把某一台机器的细节写进通用文档，下一次换机器就会把人带沟里；
而**方法**可以一直用。

**一个真实的反例（本仓库自己的）**：`things to study/makefile.include` 是一份真实的
集群编译配置，里面是 `MKLROOT=<编译器安装路径>`、`FC=<MPI 版 Fortran 编译器>`
这类**站点信息**。本项目只从它提炼了「编译要注意什么」这类通用方法。
⚠️ **本条原先把那个真实路径整个抄了进来** —— 于是它一边说"没有把任何一行
路径写进仓库"，**一边自己就把那行写了进来**。已改成占位符。
**教训：讲"不该写什么"的段落，最容易自己犯那条规矩。**

**怎么做**：立这条规矩，并且**给站点信息一个出口** ——
约定用户自己维护 `SITE.md`（见 §3），**永不进仓库**。

### 0.2 ⭐ **`POTCAR` 绝不进仓库**

依据（`references/official/pages/POTCAR.md`）：

> `Since the release of the potpaw.54 potential set (VASP version 5.4)
> POTCAR files also contain a copyright notice and a unique hash that can be
> used for verification of the file.`
>
> `The settings in the POTCAR file are read-only and must not be edited.`

⇒ **本 skill 的硬边界**：

- **不生成** `POTCAR`（`wizard.py` 只写一份 `POTCAR.README` 告诉用户怎么拼）；
- **不复制、不缓存、不写出** `POTCAR` 的任何内容；
- **只在用户自己的目录里就地读头部几个数字**（`TITEL`/`ENMAX`/`ZVAL`），
  用于：判断 `ENCUT` 是否低于 `ENMAX`、核对元素顺序、估算电子数；
- 输出里**只出现数字与元素名，绝不回显正文**。

**"宁可保守"**：一旦仓库里混进不该有的文件，后果不是技术问题。

## 1. 分层模型

| 层 | 文件 / 目录 | 角色 | 改动频率 |
|---|---|---|---|
| **G 官方权威** | `references/official/`（`pages/` 627 页、`raw/` 627 份 wikitext、`_sources.tsv`、`_keywords.tsv` 620 条） | **一手基准**，逐页采自 `vasp.at/wiki`，带来源 URL + 抓取日期 | 中（官方更新就重抓） |
| **A 决策库** | `references/decide.md`（§0–§20 + 附录 A/B） | 写输入/选方法/判读结果的**权威答案** | 低（答案稳定） |
| **F 实战手册** | `references/playbook.md` | **可执行判断层**：症状→处方 73 条、工作流 17 个、数值速查、报错速查 | 中（踩到新坑就补） |
| **B 课程综合** | `references/course_learned.md` | 讲义内化（主题式导航）+ **课程口径 vs 官方口径差异表** | 中 |
| **C 速查** | `references/course_notes.md` | 实战精华（供 grep 直击） | 低 |
| **E 原始素材** | `references/raw/`（`L1–L4.txt`、`D1–D4.txt`、`learn_L*.md`、`seg_L*.tsv`、抽取脚本） | **溯源层，原文只读** | 仅新增 |
| **案例层** | `references/cases/` | 真实生产算例登记（**不含 POTCAR**） | 仅新增 |
| **使用者文档** | `USAGE.md` | 面向人：30 秒上手 / 工具用法 / 分层查询 / FAQ | 中（受 `_doc_consistency.py` 约束） |
| **跨 agent 入口** | `AGENTS.md` + 指针文件 | **唯一真源 + 极简指针** | 中 |
| **示例** | `examples/` | 开箱即用（每个含已校验输入 + README） | 中 |
| **真机套件** | `conformance/` | 极小算例 + 生成器 + 断言 | 中 |

**黄金规则**：

1. 日常以 **G / A / F** 为准；C 仅速查；E 只在"溯源校正"时读。
2. **B 是 C 的超集** —— 新增深度内容进 B，别再往 C 堆。
3. **E 永不删** —— 它是"无遗漏"的溯源证据；发现 B 有误，**回 E 核对后改 B**，
   再视情况同步 A。
4. **F 不重复 A/B 的知识** —— 只把"可执行的判断"提炼成对照表；
   讲"为什么"回 A/B。F 的每条经验要标来源（`[L1]`…`[D4]`/`[官方]`/`[算例]`）。
5. **G 只写官方原话** —— 任何推断、经验、课程口径一律不进 G。
   **A–F 与 G 冲突时一律以 G 为准**并回修 A–F，
   在该处标注"（已按官方 G 层修正，见 `references/official/…`）"。
   官方占位页 / 404 一律**如实标注，不编造**。
6. 跨文件结论都要**打通交叉引用**（A↔B↔F↔G）。
7. 凡"经验级但无直接溯源"的结论，**显式标 `[待核对]`**，不硬塞成事实。
8. **改完文档必跑 `python _doc_consistency.py`** —— 它实测模板数 / 阶段数 /
   用例数并与文档口径比对，防数字漂移。

## 2. 新增资料的标准流程

### Phase 0 — 受理与梳理

- 列出新增文件清单，确认类型与对应关系。
- **如果含语音转写/字幕**：先建**同音错字表**（见 §4）。
- 如果资料序号 ≠ 主题序号：建**错位映射表**，后续按**主题**而非按页号重组。
- 产出可暂存 `references/raw/survey_YYYYMMDD.md`。

### Phase 1 — 抽取原始文本（落 E 层）

- **讲义 PDF → 分页文本**：
  ```bash
  python references/raw/extract_lectures.py --src "<讲义目录>" --out references/raw
  ```
  输出 `L{n}.txt`，每页前有 `========== PAGE N ==========` 标记。
  源目录用 `--src` 或环境变量 `VASP_COURSE_SRC` 指定，**不要在脚本里写死本机绝对路径**。
- **答疑 docx → 分段文本**：
  ```bash
  python references/raw/extract_qa.py --src "<答疑目录>"
  ```
  输出 `D{n}.txt`，每段前有 `========== D{n}-P{m} ==========` 标记。
- **官方 Wiki → 官方层**：
  ```bash
  python references/official/_fetch_wiki.py            # 抓取（可反复跑，续抓）
  python references/official/_discover_pages.py --fetch # 补齐分类页与主题页
  ```
- ⚠️ **铁律：抽取结果逐字保留、只统一换行为 LF，绝不加头注/尾注。**
  一旦插入任何行，"`L2.txt` 第 N 行"这个引用体系就**整体失效**。
  溯源信息（原始文件名 / 页数 / 行数 / sha256）登记到 `references/raw/README.md`，
  **不要写进 `L*.txt` / `D*.txt` 本身**。
- 核对**总页数**与空页（空页也计入"已处理"，避免漏页错觉）。

### Phase 2 — 逐页无遗漏学习（落 E 层 `learn_L*.md`）

- 派 **N 个并行 agent**（按资料份数），每个读"指定原文全文 + 对应答疑 + 已有 notes"，
  产出 `learn_L{n}.md`。
- **每个 agent 必须交两份机器可查的东西**：
  1. **页覆盖清单**（逐页 ✓，确认无遗漏页）；
  2. **主题分段表** `| 起始行 | 结束行 | 主题 | 要点 |`，
     要求**连续覆盖全文、无重叠、无空档** ——
     它同时是映射表的输入，也是"**是否真的逐行读完**"的**唯一客观证据**。
- 报告必须含 **§4 冲突与错误日志**（讲义内部 / 讲义 vs 答疑 / 排版错乱 /
  与官方不符）与 **§5 待核对清单**。
- Agent 易错点（已踩过）：
  - **PDF 抽取会把公式与上下标打散**（`Fe 3 /Al 2 O 3` 实为 Fe₃/Al₂O₃、
    `H 2 O` 实为 H₂O）—— 要求按**化学语义**还原并注明"原文排版如此"。
  - **讲义按主题切 deck，答疑按天录**，两者**多对多**；要按**主题**重组。
  - **不许为了凑格式编造**：确实没有学员问答时如实写"无"，不要虚构。

### Phase 3 — 综合内化（落 B 层 `course_learned.md`）

- 把各 `learn_L*.md` 按**主题**重组（非按页），作为导航枢纽。
- 规则：A/C/D/G 已覆盖的**只索引不重写**；讲义/答疑**独有**的公式、参数表、
  数值案例、坑，**全量收录**。
- > ⚠️ **Phase 3 的完成判据必须可机械核验（本节是 SOP 最容易失守的地方）**
  >
  > 历史教训（CP2K skill）：某轮 `learn_L*.md` 做得很好，但综合稿只吸收了一部分，
  > 文件末尾却写下"所有【新】标记项已落入本库"。复核发现多条**零命中** ——
  > **声明是假的，而且当时无人能证伪**。
  >
  > 因此现在要求：
  > 1. 用脚本把各 `learn_L*.md` 的 `【新】` 条目抽成清单；
  > 2. **逐条 grep 消费层**（`course_learned.md`/`course_notes.md`/`decide.md`/
  >    `playbook.md`），统计"已落 / 未落"；
  > 3. **禁用无限定的"全部已收录／逐行处理"这类措辞** ——
  >    宁可写"已落 X 条，Y 条暂缓（见清单）"。

### Phase 4 — 提升硬规则 / 决策（落 A 层 `decide.md`）

- 若新资料给出可复用的"必做/必避"结论，提升到 `decide.md`：
  新增小节，并在相关既有节加 `见 §XX` 交叉指针。
- 无直接溯源的经验结论：**标 `[待核对]`**。

### Phase 5 — 可执行经验（落 F 层 `playbook.md`）

- 判断标准：这条内容**能直接指导"遇到 X 就做 Y"**吗？能，就进 F。
- 每条尽量标来源；**不要把 A/B 的"为什么"抄进 F**。

### Phase 5.5 — 补官方层（落 G 层）

- 任何"官方怎么说"的问题，若 `references/official/pages/` 里没有对应页面，
  **先补抓**（跑 `_fetch_wiki.py` / `_discover_pages.py`），
  而不是凭记忆写。**查不到就写"来源待核对"或"本仓库未镜像该页"。**

### Phase 6 — 索引与元数据

- `SKILL.md` / `README.md` / `AGENTS.md` / `USAGE.md` 的索引与数字同步。
- `examples/` 新增示例须同时含 `README.md` 与已校验输入。
- **最后跑全套护栏**（见 §5）。

## 3. 站点信息出口：`SITE.md`

- 约定：用户自己维护一个 `SITE.md`（**永不进仓库**，已在 `.gitignore` 里），
  记录**这台机器/这个集群**的事实：VASP 可执行文件路径、队列名、核数、
  `module load` 的东西、赝势目录位置。
- 工具**不读** `SITE.md`；需要站点参数时一律写成 `<<<请填写>>>` 占位符。
- 这样做的理由：**猜机器细节 = 换机器就废**。现场**发现**（探针脚本），不猜。

## 4. 语音转写同音错字处理（若将来引入视频资料）

- **先建错字表再读**。高频例：`VSP`=VASP、`验室/验尸`=赝势、`机组`=基组、
  `京弯`=晶胞、`军方位1`=MSD、`镜像分布函数`=RDF、`二氧化石`=TiO₂。
- 学习 agent 的提示词里**显式给出错字表**，并要求"遇到疑似同音错字按
  **化学语义**还原，不要当字面错误处理"。
- **⚠️ 错字表必须带"出处"列（血的教训）**：不标出处会把"某一天出现的错字"
  当成**全课程通用**，后果是——
  - `差（点）`=插（点）**只**出现在讲 NEB 的那份字幕；在另一份里"差"全是正常词。
  - **一词两义**：`postcard` 在某份字幕第 65 行指 **POSCAR**、
    66–67 行指 **POTCAR** —— 机械解码会把两个**完全不同的文件**搞混
    （**对 VASP 尤其致命**）。
  ⇒ **每条错字标出处；一词多义分行列出。**

## 6. 「搜不到」≠「不存在」

**真实案例**（CP2K skill）：一份综合稿断言"某概念在两文件全文检索**零命中**、
无法溯源"，据此把一条硬规则**降级**了。后来复核发现**实际有 32 处**，
错在三处叠加：

1. **只搜了字面量** —— 转写里还有 `BSS 1`、`BSSBSS 1`、`BSSE 5差` 等写法；
2. **搜错了文件** —— 只搜了两份，内容其实在另外四份里；
3. **前提本身就错** —— 上游把该主题误归给"第 N 天"，搜索范围就跟着错了。

⇒ **立规矩**：要下"某内容不存在"的结论，**必须**
（a）列出所有可能的同音/缩写变体，
（b）跨**全部**讲义与答疑检索，
（c）在结论里**写明检索式与检索范围**。

否则只能写"**我按这些写法没搜到**"，**不能写"不存在"**，
更不能据此降级已有结论。

- `decide.md` 各节用 `见 §XX` 互链；B 与 A/F/G 之间用相对路径链接。
- 删/改某节导致编号漂移时，**全局搜旧 `§XX` 引用**并批量更新。

- ⚠️ `_audit_citations.py` **不校验 `§` 号** —— 它只校验"被引文件存在"。
  `§` 号的正确性靠人。

## 8. 文档口径维护（防数字漂移）

**历史事故**（CP2K skill）：`SKILL.md` 同一页出现"23 类特征输入"与"生成 15 类输入"
两种说法；README 写"7 类模板"而实际 8 个。根因是**数字靠手写、没有单一真值来源**。

**做法**：

- 真值**只在代码/目录里** ——
  工具子命令数看 `scripts/*.py` 的 `add_parser` 调用；
  模板数看目录里的文件；阶段数看 `wizard.py` 的 `GOALS`；
  注入用例数看 `_inject_test.py` 的 `CASES`。
- 文档里写数字时，**先跑 `python _doc_consistency.py --list` 查真值**，再照抄。
- 任何涉及这些数字的文档改动后，**必跑 `python _doc_consistency.py`**；
  它**不硬编码真值**，而是实测后比对，因此不会随版本失效。
- ⚠️ **判据只认"加粗的断言"**（`**N 条规则**`），**不认叙述句**。
  早期 `(\\d+)\\s*条规则` 会把"原来那些规则……看 13 条规则"这种**历史叙述**
  也当成"声称" ⇒ 假红（见 `CHANGELOG.md` CR-042）。
  **"描述"与"断言"是两条轴，计数检查必须只咬断言。**
- 漂移时用 `python _doc_consistency.py --fix` **一键同步**（默认只报不改）。

## 8b. ⭐ **条件性建议的写法**（规定 vs 描述；后果分档）

> 📖 **操作细则单独成页**：`references/_GATES.md`
> （三个必答问题 / 规模敏感标签清单 / 工具用法 / 三条结构性误报 / 裁定后怎么写）

> **为什么单列一节**：本项目的一次真实事故里，**知识库躺着一条把使用者
> 引向反方向的东西** —— 教程作者说「VASP 那个 `NCORE` WARNING……**无视即可**」，
> 而它在他的规模下安全、在大体系 + 多核下**直接崩**。
> 根因是**结构缺陷**：全库约 **850 处证据标记（"谁说的"）**，
> 而"**适用条件**（"什么时候成立"）"**0 处结构化字段**。
> ⇒ 「条件性建议」被当成「无条件事实」存进来，**使用者看不出区别**。

### 8b.1 规矩：每条"给指令"的条目必须能回答"什么时候不成立"

写条目时问三件事（写不出来就标 `[待核对]`）：

1. **这是"规定"还是"描述"？**
   - **规定**：在告诉使用者该怎么做 ⇒ **必须有适用条件**；
   - **描述**：在陈述某算例/讲义/答疑里出现了什么 ⇒ **不需要**条件，
     **但措辞必须让人看出是描述**（"算例一律 0.2" ≠ "你总是该用 0.2"）。
   > ⚠️ **"是不是描述"与"有没有条件"是两条不同的轴。**
   > 一条行可以**既有条件、又仍是描述**。
2. **隐含的条件属于哪一类？**
   规模（原子数/胞大小）· 体系类型 · **并行配置（核数/`NCORE`/`KPAR`/rank）** ·
   版本 · **站点/机器（内存/栈/网络/队列）** · 别的参数取值 · 赝势。
3. **条件不成立时会怎样？**（**这一档决定条目该多显眼**）

   | 档 | 含义 | 要求 |
   |---|---|---|
   | **崩** | 作业跑不起来 | 条件必须**写在最显眼处**，并给自查动作 |
   | **静默错** | 能跑完但结果错，**且不报错** | 同上；**必须给判据** |
   | **慢/贵** | 能跑对，但浪费机时 | 写明即可 |
   | **无量级影响** | 可忽略 | 不必写 |

### 8b.2 三个已知的坑（都是实测出来的）

1. **"无视即可"类框定最危险。** 跟着权威转述进来的"不用担心/可以忽略"，
   往往压掉**唯一能救命的那一行**。
   ⇒ 写这类条目时**必须同时写清**：作者说这话时的**规模/配置**是什么，
   以及**换成别的规模还成不成立**。

   > ⭐ **`A_defer` 类的标准写法（本项目实测出来的一条规矩）**
   >
   > **"可以忽略"必须配一个"什么情况下不能忽略"。**
   >
   > 最好的范例来自外部教程作者本人 —— 他写「不用担心，无视即可」之后，
   > **自己留了后门**：
   >
   > > 「……**不用担心，无视即可**。但**如果你的计算失败了**，
   > >  这个警告信息**或许**对你排查错误可能会有所帮助」
   >
   > 这正是那次事故里被跳过的那条信号。**作者留了后门，使用者没接上。**
   >
   > 本项目已按这条规矩自查了消费层里**全部 3 处** `A_defer` 命中
   > （裁定底稿见 `references/_GATES.md`），结论是**三处都已合格**：
   >
   > | 位置 | 忽略的对象 | 为什么合格 |
   > |---|---|---|
   > | `decide.md:1150` | < 50 cm⁻¹ 的虚频 | 紧邻一张**带阈值的三档表**，还给了量级论证 |
   > | `course_notes.md:130` | 气态分子最低 6 个频率的虚频 | 限定词在**同一行**（"气态分子"） |
   > | `course_learned.md:107` | 对催化无影响的自由度 | 是**讲义原话的直接引用**，且给了具体例子 |
   >
   > ⇒ **规矩是"必须有边界"，不是"必须加一句如果"。**
   > 三处都已经有边界了，**不要为了合规而堆废话** ——
   > 那会把本来清楚的一行变成谁都不读的一段。
2. **表格的「适用范围」列不要填成"结论句"。**
   `playbook.md` §0.13 的 `NCORE=1` 行曾把官方的**结论例子**
   （"≲8 核 / Gbit 以太网"）填进「适用范围」，而把真正的后果
   （官方原句 *leading to high memory usage*）降级塞进「例外/反例」列 ——
   **列装反了，而"高内存"是致命后果**（见 `CHANGELOG.md` CR-043）。
3. **规模敏感标签要专门过一遍。** 有些参数（`NCORE`/`NPAR`/`KPAR`/
   `LREAL`/`NBANDS`/`NGX`…）的**后果随核数与原子数变化**，
   它们的"建议值"天生带条件。**不要把它们和普通参数混在一张表里平铺。**

### 8b.3 工具：`_audit_gates.py`

```bash
python _audit_gates.py                 # 捞"给了指令、没写条件"的候选
python _audit_gates.py --kind E_meta   # 只看文档维护条款
```

⚠️ **它是审计工具，不是判据**——看不懂语义，产出的是**待人工裁定**的候选。
实测信噪比约 **1:12**（52 条候选里真正要改 4 条），
所以**裁定记录要落盘**（格式见 `references/_GATES.md`），
否则下一轮会把同一批**原样重捞**。

**它已知的三类结构性误报**（改检测器时按这个顺序看）：

| 误报类型 | 占比 | 判据 |
|---|---|---|
| 把"知识库怎么写"当成"计算怎么做" | ~17% | 宾语是"本文件/本文/本表" ⇒ `E_meta`（**换第二问**：时效/边界） |
| 数值表/代码块被当散文 | ~15% | 表头含 `适用范围/例外/反例` ⇒ 降级；围栏内 ⇒ 跳过 |
| 把"描述"读成"规定" | ~38% | 描述性引导词（实际/算例/讲义/原文/实测/来源…）作为**独立排除信号** |

## 10. 提交规范

- **一个改动一个提交**，消息说清"改了什么、为什么"。
- **提交消息以对外版本号开头**（如 `V0.1: …`）。
  > 理由（CP2K skill 实测）：GitHub 的文件列表只显示"**最后一次改动该文件的提交**"
  > 的消息首行。一度用工作轮次号开头，结果 167 个文件齐刷刷显示同一个轮次号，
  > 看上去像"这一版叫那个轮次号"。
- **首次入库 / 批量补文件要单独一笔**，不要和本轮实际改动混成一个大提交。
- 抓取产物（`references/official/` 的 627 页）**单独一笔提交**
  （看产物不是"我写的知识"，混在一起会污染 diff）。

### 12.2 ✅ 做法：**行数骨架**（不是正则脱敏）

`_audit_citations.py` 核对 `EX80:42` 时**只需要"篇存在 + 行号在范围内"** ——
**它不读内容**。所以发布版只保留**行数**、清空内容：

```bash
python _publish_prep.py --check              # 体检
python _publish_prep.py --make --out <临时目录>   # 生成安全占位版
# 把 <临时目录> 里的内容放进 references/raw/lvthw/ 再提交
python _publish_prep.py --restore            # 恢复原文（本地核对用）
```

**实测**：空壳上两条护栏**都仍然 `exit 0`**（引用审计 + 覆盖性）。

⛔ **绝对不要用"正则脱敏"代替它。** 实测按类别做模式替换**只清掉约 30%**：
`/home` 340→241、IP 17→12、密钥 20→16、`module load` **4→4**（一个没清掉）。
类别是**语义标签**（"集群名"），而集群名在正文里可能就是普通英文词。
⇒ **"尽力而为的脱敏"会给出 false 的信心 —— 比不脱敏更危险。**

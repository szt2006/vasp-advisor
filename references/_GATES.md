# _GATES —— 「适用条件」怎么标（**本项目的一条硬规矩**）

> **一句话**：给指令的知识条目，**必须能回答"什么时候不成立"**。
>
> 这一页是 `references/MAINTENANCE.md` §8b 的**操作细则**，
> 配套工具是 `_audit_gates.py`。

---

## 1. 为什么需要它（一次真实事故的根因）

用户报来一个真实失效：

> 179 原子 NiO-ZSM5 团簇、Γ 点、`ENCUT=400`、**16 MPI rank**、
> **没写 `NPAR`/`NCORE`**（走默认 `NCORE=1`）
> ⇒ 每个 rank 独占一个 band、独自完成整块 150³ FFT
> ⇒ **第一次 SCF 就 `SIGSEGV`**，`OSZICAR` 只有表头。
> 只加一行 `NPAR = 2` 就好了。

**本项目的离线工具原理上抓不到它**（`NPAR` 是合法标签、值域正常）。
但真正要命的不是"抓不到"，而是**知识库里躺着一条会把使用者引向反方向的东西**：

外部教程作者的原话是「VASP 都会输出一个大大的 `WARNING` 来吓唬你，
**不用担心，无视即可**」——
**他接着留了后门**：「但**如果你的计算失败了**，这个警告信息**或许**
对你排查错误可能会有所帮助」。
**作者留了后门，使用者没接上，于是跳过了唯一能救命的那一行。**

**这一条在他自己的规模下是安全的**（中小体系、少核），
但它是**一个依赖规模的建议**，而 skill 把它当**无条件建议**收了进来。

### 根因是结构缺陷（实测数字）

| 维度 | 数量 |
|---|---|
| 证据标记（"**谁**说的"）：官方 201 / 讲义 283 / 答疑 131 / 算例 163 / … | **约 850 处** |
| 「适用条件」结构化字段（"**什么时候**成立"） | **0 处** |

⇒ **skill 只记来源，不记适用条件。**
于是"条件性建议"被当成"无条件事实"存进来，**使用者看不出区别**。
这就是"顾问"失效的方式。

## 2. 标什么：三个必须能答的问题

写任何"给指令"的条目时，问这三件事（**写不出来就标 `[待核对]`**）：

### 2.1 这是"规定"还是"描述"？

| | 含义 | 要不要条件 |
|---|---|---|
| **规定**（prescriptive） | 在告诉**使用者该怎么做** | **必须有适用条件** |
| **描述**（descriptive） | 在陈述某算例/讲义/答疑里**出现了什么** | **不需要**条件，但**措辞必须让人看出是描述** |

> ⚠️ **"是不是描述"与"有没有条件"是两条不同的轴。**
> 一条行可以**既有条件、又仍是描述**。
>
> 反例（本项目实际踩过的）：
> `course_learned.md` 写「算例**一律** `POTIM=0.2`」——
> 那是在**描述那批算例**，不是"你总是该用 0.2"。
> 但三个"一律"连用，**很容易被读成规定**。

### 2.2 隐含的条件属于哪一类？

| 类别 | 例子 |
|---|---|
| **规模** | 原子数、胞大小、FFT 网格（`NGX/NGY/NGZ`） |
| **体系类型** | 金属 / 绝缘体 / 分子 / slab / 带电 / 磁性 |
| **并行配置** | 核数、`NCORE`/`NPAR`/`KPAR`、rank 数 |
| **版本** | VASP 4 / 5.x / 6.x（见 `references/VERSIONS.md`） |
| **站点 / 机器** | 每 rank 内存、栈上限、网络带宽、队列 |
| **别的参数取值** | `IBRION`、`ISIF`、`ISMEAR`、`ISPIN`… |
| **赝势** | 是否含半芯态、是否 `H.75` 这类变体 |

### 2.3 ⭐ 条件不成立时**会怎样**？（**这一档决定条目该多显眼**）

| 档 | 含义 | 要求 |
|---|---|---|
| 🔴 **崩** | 作业**跑不起来** | 条件必须写在**最显眼处**，并给自查动作 |
| 🔴 **静默错** | 能跑完但结果错，**且不报错** | 同上；**必须给判据** |
| 🟡 **慢/贵** | 能跑对，但浪费机时 | 写明即可 |
| ⚪ **无量级影响** | 可忽略 | 不必写 |

> **为什么分档比"写不写条件"更重要**：
> 一页里所有条目都拖着同样长的条件说明 ⇒ **读者全都不读**。
> 只有把"会崩/会错"的那些**顶出来**，条件才起得到作用。

## 3. ⚠️ 规模敏感标签（**必须单独过一遍**）

有些参数的**后果随核数与原子数变化**，它们的"建议值"**天生带条件**。
**不要把它们和普通参数混在一张表里平铺。**

| 标签 | 后果随什么变 | 官方/实测锚点 |
|---|---|---|
| `NCORE` / `NPAR` | **核数 × 原子数** | 官方：`NCORE=1` 时"投影函数完整存在每个 rank ⇒ **高内存**"；`NCORE ≈ √(ranks)` 降内存。经验：`NCORE=4` 对 ~100 原子；`12–16` 对 >400 原子 |
| `KPAR` | k 点数 × 内存 | 官方：k 点并行**高效但要多占内存** |
| `LREAL` | 原子数 | 官方：>~30 原子建议实空间投影，**且只用 `Auto`** |
| `NBANDS` | 原子数 × `ISPIN` | 官方默认含 `int(3/5·NELECT)`；**负磁矩时默认值有 bug**（见 `_known_issues.tsv` #51） |
| `ENCUT` | **是否变胞** | 变胞要抬（官方给 1.3×），定胞不必（见 `decide.md` §4.2 的两次订正） |
| `SIGMA` | 体系类型 + 核数无关、但随金属性变 | 官方：金属看 `entropy T*S` < 1 meV/atom |
| `IMAGES` / `SPRING` | 核数（必须整除） | 见 `playbook.md` §0.13 |
| `NGX/NGY/NGZ`（`PREC` 派生） | `ENCUT` × 晶格 | 见 `_known_issues.tsv` 里 FFT 网格相关的条目 |

⚠️ **本项目已实测出的一个反面教材**：`playbook.md` §0.13 的 `NCORE` 表
**格式太规范**（每行都有"适用范围"列）⇒ 审计器**整表跳过**了它，
而其中一行恰好**把两列装反了**、把"高内存"降级成了脚注。
⇒ **"条件写得好"可能只是"格式规范"。**
检查一条知识有没有条件，**不能看它有没有"适用范围"列，
要看那一列里填的是不是条件**。

## 4. 工具：`_audit_gates.py`

```bash
python _audit_gates.py                  # 捞"给了指令、没写条件"的候选
python _audit_gates.py --kind A_defer   # ★ 只看"无视即可"类（最危险）
python _audit_gates.py --kind E_meta    # 只看文档维护条款（换第二问）
python _audit_gates.py --show-gated     # 连"已带条件"的也列出来（对照用）
```

**四类命中的含义**：

| 类 | 形态 | 危险度 |
|---|---|---|
| `A_defer` | 「无视即可」「不用担心」「可以忽略」 | 🔴 **最高** —— 跟着权威转述进来的框定，最可能压掉一条真信号 |
| `B_absolute` | 「一律」「总是」「从不」「永远」 | 🟡 绝对化措辞几乎总是过度概括 |
| `C_value` | 「设成 N」「取 N」+ 单位 | 🟡 数值建议几乎都依赖规模/体系/站点 |
| `D_scale` | 「不适用」「受限于」「只能（用于…）」 | 🟡 已经在讲限制，但没给**边界在哪** |
| `E_meta` | 宾语是"本文件/本表"的**维护规矩** | ⚪ **换第二问**：时效 / 边界 |

### ⚠️ 它是**审计工具，不是判据**

- 它**看不懂语义**：一条建议完全可能隐含条件而无需写出来
  （例如「`ISMEAR` 默认 0.2」是**官方定义**，不需要条件）；
- **「没有门」不等于「错了」**，只等于「**该看一眼**」；
- **实测信噪比约 1:12**（52 条候选里真正要改 4 条）。

⇒ **所以裁定记录必须落盘**（本文件 §「后果四档」给出格式），
否则下一轮会把同一批**原样重捞**。

### ⚠️ 三条已知的**结构性**误报（改检测器时按这个顺序看）

| 误报类型 | 占比 | 判据 |
|---|---|---|
| 把"知识库怎么写"当成"计算怎么做" | ~17% | 宾语是"本文件/本文/本表" ⇒ `E_meta` |
| 数值表 / 代码块被当散文 | ~15% | 表头含 `适用范围/例外/反例` ⇒ 降级；``` 围栏内 ⇒ 跳过 |
| 把"描述"读成"规定" | ~38% | 描述性引导词（实际/算例/讲义/原文/实测/来源…）作**独立排除信号** |

### ⚠️ `A_defer` **不参与** gated 过滤（这是一条刻意的设计）

B/C/D 类"附近有条件"就算写了条件；
但 **`A_defer` 是"叫你忽略某个信号"** ——
它的危险恰恰在于**读者看到了附近的那个条件，却没把它与"忽略"联系起来**
（那次事故就是这么发生的）。
⇒ **`A_defer` 一律保留在候选里**，并用 `soft` 标出"附近有条件"。

**历史教训**：最早版本里三条 `A_defer` 命中**全部被判成 gated 而滤掉** ——
也就是说，**造成那次事故的那一类，在默认输出里根本看不见。**

## 5. 裁定之后怎么写

判定"确实缺条件"的条目，按**后果分档**决定改法：

- 🔴 **崩 / 静默错** ⇒ 把条件写在**条目的最前面**，并给**可执行的自查动作**
  （一条 `grep`、一个判据），而不是一句"注意适用条件"。
- 🟡 **慢/贵** ⇒ 在条目里写明即可，**不要**升级成警告。
- ⚪ **无量级影响** ⇒ **不写**。

⚠️ **不要为了合规而堆废话。**
本项目自查了消费层里全部 3 处 `A_defer` 命中，**结论是三处都已合格**
（每处都已经有边界：一张带阈值的三档表 / 同一个行内的限定词 / 讲义原话的直接引用）。
**规矩是"必须有边界"，不是"必须加一句如果"。**

> **`A_defer` 类的模范写法**（来自那次事故的作者本人）：
>
> > 「……**不用担心，无视即可**。但**如果你的计算失败了**，
> >  这个警告信息**或许**对你排查错误可能会有所帮助」
>
> **"可以忽略"后面必须跟一个"什么情况下不能忽略"。**

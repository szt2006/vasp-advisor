## 2. 抽取铁律（与 `extract_lectures.py` / `extract_qa.py` 一致）

> **逐字保留、只统一换行为 LF、绝不加头注/尾注。**

一旦插入任何行，`EX80:42` 这类**引用就整体失效**。
溯源信息登记在**本文件**，**不要写进 `*.txt` 本身**。

### ⭐ 行号口径（**这条踩过坑，务必看清**）

本层的行号 = **物理行数** = 文件里 `\n` 的个数
（等价于 `for line in fh` / `str.splitlines()` / `wc -l`）。

⚠️ **不要用 `text.split("\n")` 数** —— 因为文件以 `\n` 结尾，
它会多出一个**末尾空串**，使行数 **+1**。
这个 ±1 差异真实造成过问题（见 `CHANGELOG.md` 的 **CR-025**）：

- `_audit_citations.py` 会说"你引到了第 493 行，文件只有 492 行"；
- `_check_coverage.py` 会说"止行超过总行数"。

两边其实都没错，是**口径没统一**。现在三处（抽取脚本 / 引用审计 / 覆盖核查）
**统一用物理行号**。

### ⭐ 覆盖性核查（**"真的读完了"的客观证据**）

```bash
python _check_coverage.py               # 全部
python _check_coverage.py --family lvthw # 只看本层
python _check_coverage.py --tsv references/raw/lvthw/seg_G6.tsv
```

它核查每条分段的**行区间是否连续覆盖该篇全文、无重叠、无空档、无越界**，

> **为什么这条重要**：这两条是"是否真的逐行读完"的**唯一客观证据**。
> 没有它们，"我读完了"就只是一句**无法被证伪的声明**。

⚠️ **它只查覆盖性**：证明"行区间没漏"，**不证明**"内容读懂了"。

## 5. ⚠️ 站点信息：本层逐字保留，**消费层不得复制**

这是**网站导出**，Shell 提示符里带大量现场信息。实测（`SITEINFO.tsv`，673 条）：

| 类型 | 条数 | 消费层该怎么写 |
|---|---|---|
| `/home/<user>` 路径 | 329 | 用 `~` 或 `<你的目录>` |
| 具体超算/集群名 | 89 | 只写「你的集群」 |
| QQ群/公众号 | 71 | **不进消费层** |
| 邮箱 | 39 | **不进消费层** |
| `账号@主机` | 37 | 用 `<账号>@<主机>` |
| `/opt/...` 路径 | 33 | 只写「按集群文档」 |
| 排队系统命令 | 21 | 可写「用排队系统提交」，**不写队列名/核数上限** |
| IPv4 地址 | 17 | **绝不出现** |
| 密钥相关 | 16 | **绝不出现**（含路径） |
| 远程传输命令 | 13 | 可提方法 |
| VPN | 4 | 可写「需要 VPN」 |
| `module load` 具体模块名 | 4 | 只写「加载 MPI/编译器」 |

### 规矩（`references/MAINTENANCE.md` §0.1「机器细节不进，结论进」）

- **本层（`*.txt`）逐字保留** —— 归档层的职责就是"原样"。**不要改。**
- **消费层**（`references/decide.md` / `playbook.md` / `course_*.md` /
  `learn_G*.md` 的正文）**不得复制这些细节**，一律写成占位符
  `<你的集群>` / `<账号>@<主机>` / `~/...`。
- 需要写命令示例时，**提示符脱敏**：`<user>@<cluster>:~/ch4$ grep ...`。
- `_doc_consistency.py --scan-leaks` 会扫仓库，但**本层被显式排除**
  （理由：归档层不是"我们写的东西"，把它报成泄漏会制造永远消不掉的红灯）。
  ⇒ **本层的站点信息靠"人工审查 + 上面的清单"，不靠自动扫描。**

### 关于 `POTCAR`

`A05` 那篇是"自动生成 `POTCAR` 的脚本"，正文里含
**赝势数据集名字的回显**（形如 `TITEL = PAW_PBE Cu 22Jun2005`）。

- 这些**不是** `POTCAR` 的数据内容，只是 `grep TIT POTCAR` 的输出示例；
- 本层**逐字保留**它们（归档层）；
- **消费层不得复制** —— 本项目的边界是
  「**不生成、不复制 `POTCAR`**」（`MAINTENANCE.md` §0.2）。
  `A05` 那个脚本的可采纳/不可采纳分界见 `learn_G8.md` §3。

### ⚠️ 一条重要的能力边界：**大量关键内容只在截图里**

多位精读员独立报告过同一件事：LVTHW 很多**报错原文、`INCAR` 全文、脚本源码、
表格**是**以图片**形式给出的，文本层**取不到**。已登记的例子：

- `EX10` / `EX12` 的**报错原文**在截图里；
- `EX17` 的**两份 `INCAR` 全文**在截图里 ⇒ **"提高精度"到底改了哪个参数无法确认**；
- `EX34` / `EX35` 的**脚本源码**在截图里；
- `EX36` 的 `ISIF` 对照表在截图里；
- `EX51` 关于 `LVTOT` vs `LVHAR` 差异的**具体 eV 数**只有图；
- `EX69` 的**熵脚本**作者故意只给图片（他明说"不要问我要现成的"）。

⇒ **引用这些内容时必须标注"原文为截图，文本层未核实"**，
不要把它当成可逐字复核的证据。这是本层的**已知短板**，
也是把相关条目标 `[待核对]` 的原因。

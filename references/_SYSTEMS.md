# _SYSTEMS —— **体系类型索引**：先问「你算的是哪类体系」

> **这一页解决什么问题**：本 skill 的知识原来是**按来源**组织的
> （`official/` / 讲义 / 答疑 / 算例 …），那是为了**可回溯**，没错。
> 但**使用者不是这么想的** —— 他想的是「我算的是个 179 原子的金属氧化物
> 团簇，该注意什么」，而不是「官方第 37 页说了什么」。
>
> ⭐ **工具书的第一层索引不该是「来源」，也不该是「参数名」，而是「你算的是什么」。**

---

## 怎么用这一页

```bash
python _system_types.py --lookup <你的算例目录>   # 判断属于哪类 + 给该类画像
python _system_types.py --survey                 # 看全部算例的类型分布
python _system_types.py --derive --write         # 重新生成本页
python _system_types.py --check                  # 校验本页数字与实测一致
```

⚠️ **本页每一条数字都是脚本从真实算例实测出来的**（可 `--check` 复核），
**不是我的建议**。凡涉及「该注意什么」的断言，都**挂到已有条目上**（给位置）。

## 本库真实翻车记录（**98 个算例里 8 个报 ERROR**）

这是「该注意什么」**最硬的证据来源** —— 不是推测，是实测。

| 检查项 | 命中算例数 | 意味着什么 |
|---|---|---|
| `XSPECIES.counts` | 3 | `POTCAR` 数据集数与 `POSCAR` 元素种类数**对不上** |
| `XMAGMOM.count` | 2 | `MAGMOM` 个数 ≠ `POSCAR` 原子总数（**静默失效**：程序自己补/截断） |
| `INCAR.annotation_in_value` | 2 | 值里混进说明文字（**从 wiki 抄代码块的经典错误**） |
| `INCAR.semicolon_comment` | 2 | 行内注释含分号 ⇒ 后面被当成新 tag |
| `INCAR.unknown_tag` | 1 | 标签 VASP 不认（⚠️ **老版本会静默忽略**） |

⇒ **跑一次 `python scripts/validate.py <你的目录>` 就能查完这五项。**

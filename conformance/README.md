# conformance —— 真机一致性套件

> **这一层回答的是：`validate.py` 报 `OK` 的那些输入，真程序真的接受吗？**
>
> ⚠️ **本目录在当前构建环境里没有跑过** —— 因为构建环境里**没有 VASP**。
> 这不是"没来得及做"，而是"**必须有真程序才能做**"。
> 所以本 README 的定位是：**告诉你缺口在哪、以及怎么补**。

---

## 1. 为什么必须有这一层（三层可核对性）

| 层 | 需要什么 | 能抓什么 | 抓不到什么 |
|---|---|---|---|
| **引用的可回溯性** | 无 | 论断能否回原文（页码/段号/行号） | 语义 |
| **语义自洽** | 无 | 编码、声明缺失、相关设置互相矛盾 | "写的位置不对" |
| **归属与真机** | **官方 schema / 真的程序** | "语法全对但程序不接受" | 物理正确性 |

> **关键认知：前一层在原理上抓不到后一层的错。**

本项目的实测教训（也是这个 skill 存在的理由）：

> 有 agent 拿生成的输入、看到 `validate.py` 报 `OK`、据此上了集群、**白跑一趟**
> —— 因为那个 `OK` 的真实含义只是"语法与关键字拼写没问题"，
> 而缺陷恰好在它**没检查**的那一层。

**离线校验在原理上抓不到"语法全对但程序不接受"。** 这一层就是补这个缺口的。

---

## 2. VASP 没有 CP2K 那样的官方 schema —— 这决定了本层的形态

| | CP2K | VASP |
|---|---|---|
| 官方机器可读 schema | **有**（`cp2k_input.xml`） | **没有** |
| 能做什么 | 自动生成"段 → 合法子段/关键字"表，把**归属错误**前移到本地 | 只能**机器枚举官方 wiki 的分类页**（`Category:INCAR tag`），得到一份**已知不完整**的关键字集 |
| 本项目的做法 | — | 抓 `Category:INCAR tag` → `references/official/_keywords.tsv`（620 条），做**归属校验**；对"不在表里"的分三档报 |

⇒ 因为 VASP 没有 schema，**本层（真机）不是"可选增强"，而是查归属/兼容性的主要手段**。
`references/decide.md` §1.2 有完整说明。

## 3. 应该放什么（设计说明）

### 3.1 极小算例（**卡发现场生成，不要存静态文件**）

> **静态卡片会过期** —— 生成器改了、卡片没跟着改，检查就在验证**历史**而不是**现在**。
> （CP2K skill 实测过：一批旧卡片在生成器演进后开始报错，
> 而仓库里**没有对应的生成器**，只能手工修。）

所以本目录的设计是：**一张生成脚本 + 一组断言**，而不是一堆存下来的输入文件。

**最小算例的选择原则**：

| 算例 | 抓什么 | 为什么它小 |
|---|---|---|
| Si 块体 单点 | 基线：能起来、能量是有限数、力平衡 | 2 原子 |
| Si 块体 弛豫 | 离子步能走、`EDIFFG` 能生效 | 2 原子 |
| 分子（如 CO）单点 | `ISMEAR=0`+小 `SIGMA` 的路径、`ISPIN` 分支 | 2 原子 |
| 金属 slab 单点 | `ISMEAR=1` 路径、`LDIPOL`/`Selective dynamics` | ~10 原子 |
| **把所有可选开关一次全开** | 任何一个开关的产物非法，它就会红 | 尽量小 |

> 最后那张卡**成本极低、覆盖极广**，是这一层最值得先做的东西。

### 3.2 断言什么（**四类**）

对每个算例，跑完之后断言：

1. **正常收尾**：`OUTCAR` 里有 `General timing and accounting informations`；
   **退出码为 0**（不是"跑了就行"）。
2. **无崩溃**：`OUTCAR`/`LOG` 里**没有** `VERY BAD NEWS`、
   没有 `ZBRENT: fatal error`、没有 `internal error in subroutine`。
3. **`SCF` 真的收敛**：`OUTCAR` 里
   `aborting loop because EDIFF is reached` 的**次数 == 离子步数**。
   （注意：这个标记在 `OUTCAR`，**不在 `OSZICAR`** —— 本项目为此返工过一次。）
4. **物理不变量成立**：
   - **能量是有限数**（不是 `NaN`/`Inf`）；
   - **孤立体系力平衡** `|ΣF| / max|F| < 阈值`（阈值**必须先标定**，见 §4）；
   - 其他可选项：整体平移不变性（多跑 1 个单点）。

### 3.3 用法约定

- **可执行文件路径由用户给**：
  ```bash
  python conformance/run_conformance.py --vasp /path/to/vasp_std
  ```
  未给时**友好提示 + `exit 3`**。
- **绝不写死任何站点信息**（见 `references/MAINTENANCE.md` §0.1）。
  队列名、核数、`module load` 一律由用户提供或写成 `<<<请填写>>>`。

## 4. ⭐ 本层最重要的工作：**标定阈值**

本项目有**一批阈值是 `[经验]` 或"未标定"** 的，它们现在**默认只报 WARN**：

| 阈值 | 现在状态 | 在哪 |
|---|---|---|
| 力平衡 `|ΣF| / max|F|` | **未标定** | `scripts/compare.py` 的 `F.balance_isolated` / `F.balance_relative` |
| 虚频"噪声 vs 真虚频"的分界 | `[经验]`，无官方依据 | `references/decide.md` §13.3 |
| 真空层"偏薄"的两个界（4 Å / 10 Å） | `[经验]` | `scripts/diagnose.py` 的 `WRONG.vacuum_too_small` |
| `ENMAX` 异常高的分档（1000 eV） | `[经验]` | `scripts/validate.py` 的 `XENCUT.enmax` |
| 带隙判定的 `Egap > 0.05 eV` | `[经验]` | `scripts/diagnose.py` 的 `WRONG.ismear_insulator` |

### 怎么标定（**正例/反例成对做**）

```
1. 造一个「已知正确」的极小算例 → 记下该量的值 → 这是**下界**
2. 造一个「已知错误」的算例（人为引入一个你确定的缺陷）→ 记下该量的值 → **上界**
   例如：
     · 力平衡：故意把某个原子的坐标在 POSCAR 里改一点点，
       或者用两个不同 ENCUT 跑同一个结构，看 |ΣF| 怎么变
     · 真空层：把真空层从 15 Å 逐步减到 5 Å，看表面能/功函数怎么漂
     · 带隙：拿一个已知带隙的体系（Si、MgO）对照
3. 在上下界之间选一个阈值，并把**两个算例都固化成注入用例**
   （加到 `_inject_test.py`，这样以后改代码时它会被重新验证）
4. **把阈值从 WARN 提升为 ERROR**，并在代码注释里写清
   "这个数是在什么体系上标定的"
```

> ⚠️ **第 3 步不能省。** 标定完不固化成注入用例，下次改动就会悄悄失效 ——
> 那正是"看着在检查、其实没检查"。

## 5. 本目录**现在**的状态（诚实说明）

| 项 | 状态 |
|---|---|
| 极小算例生成器 | **未实现**（见下） |
| 真机断言脚本 | **未实现**（见下） |
| 阈值标定 | **未做** —— 需要真程序 |
| 本目录在构建环境里跑过吗 | **没有**（构建环境无 VASP） |

**为什么不实现生成器？** 因为生成"极小算例的四件套"需要 `POTCAR`，
而 `POTCAR` **受许可保护、不得再分发**（见 `references/decide.md` §1.1 与
`MAINTENANCE.md` §0.2）。所以生成器必须在**用户自己的机器上**跑、
用**用户自己的 `POTCAR`**。

⇒ **正确形态**是：生成器**复用 `scripts/wizard.py`**（它已经能生成
除 `POTCAR` 外的三个文件），本目录只补：

1. 一个 `run_conformance.py`：调 `wizard.py` 生成 N 个极小算例 →
   调真程序 → 按 §3.2 断言 → 打印结果；
2. 一组阈值常量（标定后填）；
3. 把结果回流到 `_inject_test.py` 当注入用例。

**在有人真的跑过之前，本目录的 README 就是它的全部内容** ——
这比放一个跑不了、也没跑过的脚本更诚实。

## 6. 你可以怎么帮忙（最缺的三件事）

1. **跑一遍极小算例**，把 `OUTCAR` 里这几样报回来：
   - 有没有 `General timing`；
   - `aborting loop because EDIFF is reached` 出现几次、离子步几个；
   - 最后一个有力表的离子步的 `total drift` 与 `max|F|`；
   - 你的 VASP 版本（`OUTCAR` 第一行）。
2. **标定一个阈值**（§4 任选一个），把正例/反例的数据报回来。
3. **报告"程序不报错但结果不对"的实例** —— 这是最值钱的一类知识
   （见 `references/decide.md` 与 `playbook.md` §1.6）。
   **请附上你观察到的东西与排除过程**，不要只给结论。

**反馈回来的东西会被写进哪里**：

- 症状→处方 → `references/playbook.md` §1；
- 阈值 → 对应脚本的常量 + 一条注入用例 + `CHANGELOG.md` 的记录；
- 与现有说法冲突 → **先核实再改**，并在 `CHANGELOG.md` 留更正记录。
